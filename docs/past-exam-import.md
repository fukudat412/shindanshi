# 過去問の取り込み（/admin/import）

管理画面の「過去問の取り込み」に、JSON の配列を貼り付けて取り込む。

- 同じ「科目・年度・問番号・設問番号」の問題がすでにあれば更新し、なければ追加する。
- 1 件でもエラーがあれば何も書き込まない。エラーは何件目の何が悪いかで表示される。
- 取り込んだ問題は過去問（PAST_EXAM）になり、検証状態に関係なくすぐ出題される。
- 図（`images`）は、取り込むたびに入力の内容で作り直す。`images` を書かずに取り込み直すと、その問題の図はなくなる。
- 検証済み（VERIFIED）でない問題の解説には、「AI が作成した、まだ確認していない解説」という注意書きが付く。解説を確かめたら、管理画面のクイズ一覧で検証済みにする。

## 年度別セット（本番形式）

取り込んだら、管理画面の「過去問管理」（/admin/exams）で「過去問から年度別セットを作る」を押す。年度・科目ごとに問題番号順のセットができ、/exams から本番と同じ試験時間（企業経営理論・運営管理・中小企業経営・政策は 90 分、ほかは 60 分）で通しで解ける。選択肢は並べ替えず、ア・イ・ウ…の元の順で出る。押し直すと、同じ年度・科目のセット（第 1 回）の問題を入れ直す。

取り込んでいない問題（すべての受験者を正解とした問題など）があるので、点数は本番の配点とは一致しない。

## 問題の入手先

1 次試験の問題と正解は、日本中小企業診断士協会連合会のサイトで科目ごとの PDF として公開されている（2007〜2026 年度。解説はない）。

- 問題: https://www.jf-cmca.jp/contents/010_c_/shikenmondai.html
- 正解: 各年度の「正解と配点」ページ（例: https://www.jf-cmca.jp/contents/010_c_/010_c_r08_shiken/R08_1ji_shiken_kaitou.html ）

個人の学習用にローカルで使う前提。サイトの規約で商用利用は禁止されているので、取り込んだ問題を公開しない。

## 公式 PDF から変換するときの決まり

新しい年度を足すときも、同じ決まりで変換する（Claude に頼む場合も、この節を渡せばよい）。

- 問題文・選択肢は原文どおり。言い換え・要約をしない。解説は公式にないので作らない
- 設問がある問題は、共通の文章を各設問の `question` に含める
- 空欄は【Ａ】、番号付きの下線部は「［…］①」、会話は「甲氏：…」の形。表は「項目：値」の行や全角スペース区切りの行にする（画面は Markdown を解釈しないが、改行と空白はそのまま表示する）
- 図・グラフ・大きい表・複雑な表は、問題 PDF から PNG に切り出して `images` に入れる（150dpi・グレースケールで、1 枚 100KB 前後になる）。図の題名・凡例・「出所：」は画像に含め、問題文に重ねて書かない
- 選択肢そのものが図のときは、選択肢の図を記号ごと画像にし、`choices` を `["ア", "イ", "ウ", "エ"]` のように記号だけにする
- 正解が 1 つに決まらない問題（「すべての受験者の解答を正解」など）は入れない
- 取り込む前に、正解表の記号の位置と `answer` が選択肢の何番目かが一致するかを確かめる

## 解説の書き方（AI に頼むとき）

公式の解説はないので、AI に書かせて `explanation`・`choiceExplanations`・`basis`・`basisYear` に入れる。画面では「AI が作成した、まだ確認していない解説」と表示される（検証済みにすると消える）。

- 正解は公式の正解表どおり。正解を変えない。納得できない問題は、公式の正解に沿って書いたうえで別に控える
- 選択肢を記号（ア・イ…）で指さない。出題画面では選択肢を並べ替えて A・B… と表示するので、記号では伝わらない。中身で指す（選択肢が図で記号だけの問題は例外）
- 計算問題は計算過程を書き、必ず検算する
- 統計の数値・条文番号・制度の細かい要件は、確信があるときだけ書く。法令は出題年度の時点の内容で説明し、その後の改正を知っていれば一言添える
- Markdown の記法は使わない（改行と空白はそのまま表示される）

## 例

```json
[
  {
    "articleId": "cmk1j135p0008m8u2blnnfw1t",
    "examYear": 2025,
    "examQuestionNumber": 12,
    "examSubQuestionNumber": 1,
    "quizType": "MULTIPLE_CHOICE",
    "question": "（問題文）",
    "choices": ["（選択肢アの文）", "（選択肢イの文）", "（選択肢ウの文）", "（選択肢エの文）"],
    "answer": "（選択肢ウの文）",
    "explanation": "（全体の解説）",
    "choiceExplanations": ["（アの理由）", "（イの理由）", "（ウの理由）", "（エの理由）"],
    "basis": "（根拠の条文・通達など）",
    "basisYear": 2025,
    "images": ["iVBORw0KGgo…（PNG を base64 にした文字列）"]
  },
  {
    "articleId": "cmk1j17vo002hm8u2lrsc3kki",
    "examYear": 2024,
    "examQuestionNumber": 3,
    "quizType": "TRUE_FALSE",
    "question": "（正誤を問う文）",
    "answer": "false"
  }
]
```

## 項目

| 項目 | 必須 | 内容 |
|---|---|---|
| `articleId` | ○ | 問題をぶら下げる記事の ID。科目は記事から決まる |
| `examYear` | ○ | 試験の年度（西暦、2001〜2100）。画面では和暦で表示される |
| `examQuestionNumber` | ○ | 第何問か（1 以上） |
| `examSubQuestionNumber` |  | 設問番号（1 以上）。設問がなければ書かない |
| `quizType` | ○ | `MULTIPLE_CHOICE`・`TRUE_FALSE`・`SHORT_TEXT`・`NUMBER` |
| `question` | ○ | 問題文 |
| `answer` | ○ | 正解（文字列）。下の決まりを参照 |
| `choices` |  | 選択肢（文字列の配列）。`MULTIPLE_CHOICE` では 2 つ以上必要で、同じ文字列は使えない |
| `explanation` |  | 全体の解説 |
| `choiceExplanations` |  | 選択肢ごとの解説。書くなら `choices` と同じ数・同じ順 |
| `basis` |  | 根拠（条文・通達など） |
| `basisYear` |  | 根拠の基準年度（1900〜2100） |
| `topicId` |  | 論点の ID |
| `images` |  | 図。PNG を base64 にした文字列の配列（10 枚まで、1 枚 2MB まで）。問題文の下に、配列の順に表示される |

`answer` の決まり:

- `MULTIPLE_CHOICE`: `choices` のどれかと完全に同じ文字列にする。記号の `"ウ"` だけでは通らない（選択肢が図で、`choices` が記号だけのときを除く）
- `TRUE_FALSE`: `"true"` か `"false"`
- `NUMBER`: 数値として読める文字列（`"1500"`。カンマは入れない）

選択肢は表示のたびに並べ替えられるので、頭の記号（ア・イ・ウ…）は外して書く。選択肢の中の a・b や A・B などの記号は残す。

## 記事 ID の調べ方

```bash
docker compose exec -T db psql -U shindanshi -d shindanshi -At -F ' | ' \
  -c 'select s.name, a.title, a.id from articles a join subjects s on s.id = a.subject_id order by s."order", a."order";'
```

`npm run db:studio` で articles テーブルを開いても確認できる。
